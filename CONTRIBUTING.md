# Contributing to hyperOpenSeadragon

Thanks for your interest. Bug reports, questions, feature ideas and pull requests are all welcome.

## Getting help and reporting bugs

Open an [issue](https://github.com/chuang44-tiff/hyperOpenSeadragon/issues). For a bug, please include:

- what you did, what you expected, and what happened instead;
- your browser and version, and your operating system;
- for tile-generation problems, the image type (bit depth, channel count, single files or a multi-page TIFF stack) and the full error output;
- a screenshot or the browser console output if the viewer misbehaves.

If you can reproduce the problem with the bundled demo dataset (`demo_data/`, opened by `zstackHyper.html` as shipped), say so: that makes it much easier to track down.

## Proposing changes

For anything larger than a small fix, please open an issue first so we can agree on the approach. Then:

1. Fork the repository and create a branch.
2. Make your change, with a test where one is practical (see below).
3. Run the test suite and make sure it passes.
4. Open a pull request that describes what changed and why. Continuous integration runs the same tests on every pull request.

## Development setup

```bash
conda env create -f environment.yaml      # Python 3.11, pyvips, numpy, flask, pyyaml
conda activate hyperOSD
python -m pip install -r tests/requirements-test.txt
python -m playwright install chromium
```

The viewer is static HTML and JavaScript: there is no build step. Open `zstackHyper.html` in a browser, or serve the repository root (`python -m http.server`) and browse to it.

## Running the tests

```bash
python -m unittest discover -s tests -t .
```

or one module at a time, for example `python -m unittest tests.test_viewer_smoke`. See [tests/README.md](tests/README.md) for what each module covers. Set `HYPEROSD_REQUIRE_ALL=1` to turn a missing dependency into a failure instead of a skip, as CI does.

## Things to know before you change the code

- **Two viewer pages.** `zstackHyper.html` is the hand-configured viewer, and `templates/zstackHyper.html` is the template the tile generator fills in for each dataset. Apart from the DATASET CONFIGURATION block at the top, a change to one almost always belongs in the other as well. The annotation blocks (between the `ANNOTATION-` markers) must stay byte-identical; `tests/test_static_hosts.py` checks this.
- **Script load order is load-bearing.** The NIST filter bundle embeds an older OpenSeadragon that overwrites OpenSeadragon 6 when it loads; the pages snapshot and restore OpenSeadragon around it. Do not reorder the script tags.
- **Minified bundle.** The pages load `openseadragon/openseadragon-filtering-nistfuncs-12ch.min.js`, which is built from the unminified file next to it. If you change the unminified bundle, regenerate the minified copy (from `openseadragon/`):
  ```bash
  terser openseadragon-filtering-nistfuncs-12ch.js --compress --mangle --keep-fnames \
         --keep-classnames --comments some --ecma 5 -o openseadragon-filtering-nistfuncs-12ch.min.js
  ```
- **Tiles.** Generated tiles are 1024 px PNGs and the descriptor is named `stitch.xml`. Keep both when changing `generate_dzi.py` or `dzi_app.py`.
- **Demo dataset.** `demo_data/` is generated by `make_demo_data.py` and checked by `tests/test_demo_data.py`. If you change the generator, regenerate the data (`python make_demo_data.py`) and commit both.
- **Security.** `dzi_app.py` treats dataset paths as untrusted input. Keep its path-containment checks, which `tests/test_dzi_pipeline.py` exercises.
- **Third-party code.** Vendored libraries are listed in [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Do not add a dependency without recording its licence there.

## Code style

Match the surrounding code: plain browser JavaScript loaded with `<script>` tags in the viewer (no modules, no bundler), four-space indentation in Python, and comments that explain *why* rather than *what*. Commit messages are short and imperative, with a prefix such as `fix:`, `feat:`, `docs:` or `test:`.
